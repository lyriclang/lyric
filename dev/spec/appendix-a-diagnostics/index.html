    Appendix A — Diagnostic catalogue

    Generated from the toolchain's diagnostics.toml by tooling/diagnostics/appendix.py; not edited by hand. Source of the decisions: 11 Tooling and interop G9.

    Every code the reference toolchain reports, with its severity, the chapter whose rule it is, and when it is reported. The code and the severity are contract; the message's wording is not (16 §1). lyric explain CODE prints a code's whole entry: its explanation, a program that reports it and the program put right. A retired code is no longer reported, and its number is not given again.

    Severities: E error, W warning, H hint, P panic (at run time, exit code 101).

    A.1 LEX — Lexical errors

    The lexer's: a token that cannot be formed.

    Code S Chapter Title When
    LYR-LEX0001 E 01-lexical a character that starts no token, or a name beyond ASCII The source holds a character that begins no token ($, a backtick, a control character), or a word holding letters, digits or marks beyond ASCII. A word beyond ASCII is refused once where it stands and read as the name it would be.
    LYR-LEX0002 E 01-lexical a block comment that is not closed A /* comment runs to the end of the file without its */. Block comments nest, so a /* inside one needs its own */ as well.
    LYR-LEX0003 E 01-lexical a numeric literal with a suffix that does not fit it A number carries a suffix that is no type's (10i7), an integer suffix on a float literal (1.5u8), or a float suffix on a literal with a base prefix (0b1f32).
    LYR-LEX0004 E 01-lexical a base prefix with no digits after it A literal is written 0x, 0o or 0b and no digit of that base follows the prefix.
    LYR-LEX0005 E 01-lexical a digit separator right after a base prefix A literal with a base prefix has _ directly after the prefix, as in 0x_FF.
    LYR-LEX0006 E 01-lexical an exponent with no digits A decimal literal has an e or E, perhaps with a sign, and no decimal digit after it: 1e, 2.5e+.
    LYR-LEX0007 E 01-lexical a malformed escape sequence A string, character or f-string holds a \ that starts no escape (\q), a \x without two hex digits, or a \u that is not \u{…} with one to eight hex digits naming a Unicode scalar value (at most 10FFFF, no surrogate).
    LYR-LEX0008 E 01-lexical a character literal that holds no character or several Between the quotes of a character literal stand no characters ('') or more than one ('ab'). An escape counts as one.
    LYR-LEX0009 E 01-lexical a string literal that is not closed A string, raw string or byte string reaches the end of its line or of the file without its closing quote; a multi-line string """… reaches the end of the file without its closing """.
    LYR-LEX0010 E 01-lexical a character literal that is not closed A character literal reaches the end of its line or of the file without its closing '.
    LYR-LEX0011 E 01-lexical an f-string that is not closed An f-string reaches the end of its line (or, for f""", of the file) without its closing quote — also when the line ends inside an interpolation or its format spec.
    LYR-LEX0012 E 01-lexical a byte string holding no byte, or an '@' without a name A byte string b"…" holds a character beyond ASCII or a \u{…} escape, which name characters and not bytes; or an @ is followed by neither a name nor [.
    LYR-LEX0013 E 01-lexical a byte escape in a string or character A string, character literal or f-string holds the escape \xNN, which writes a byte and stands in a byte string b"…" only.
    LYR-LEX0014 E 01-lexical a multi-line string whose quotes do not stand on lines of their own A multi-line string """…""" has text on the line of its opening """, or text before its closing """ on the closing line.
    LYR-LEX0015 E 01-lexical a line of a multi-line string indented less than its closing quotes A line of a multi-line string (or a multi-line f-string) does not begin with the indentation of the line that holds the closing """. A blank line may be indented less.
    LYR-LEX0016 E 01-lexical a float literal without digits on one side of its point A float literal is written 1. or .5. Each is refused once and read as the float it means.

    A.2 PAR — Syntax errors

    The parser's. A declaration that does not parse reports these and nothing that follows from them (16 §2).

    Code S Chapter Title When
    LYR-PAR0001 E 02-grammar a token after one whole expression, pattern or statement (retired) The parser was asked for exactly one expression, pattern or statement, and a token follows it. Retired: Lyric 5 parses a file whole; the single-item entry points that report it serve std.syntax and a macro's read-back, which turn any parse error into LYR-CT0001 or an internal error
    LYR-PAR0002 E 02-grammar an expression is missing An expression is needed — after =, as an argument, an operand, a returned value — and the token there begins none.
    LYR-PAR0003 E 02-grammar a member name or a compile-time form is incomplete A . or ?. is followed by no member name (or by a number that is no tuple position), or the parts of a compile-time form are missing: the parentheses of comptime if or comptime for in an initializer, the ] of e.[f], the field and = of a with.
    LYR-PAR0004 E 02-grammar a ']' is missing A [ is not closed: an array literal, an index, an array pattern, an array type, a throws or catch list, a type set in a pattern, a constraint or conformance list, a bound, or T.[f].
    LYR-PAR0005 E 08-expressions range operators chained A range a..b or a..=b is followed by another range operator, as in 1..5..9.
    LYR-PAR0006 E 01-lexical a numeric literal with an unknown suffix A numeric literal ends in letters that are no suffix. The lexer refuses such a literal first (LYR-LEX0003, LEX0004, LEX0006), so this code comes only together with that one.
    LYR-PAR0007 E 01-lexical a numeric literal too large An integer literal does not fit in 64 bits, or a float literal is beyond the range of float.
    LYR-PAR0008 E 02-grammar a parenthesis is missing A ( or ) the construct needs is missing: a call, a grouping, a tuple, a parameter list, a function type, the condition of if or while, a for header, a catch binding, a pattern.
    LYR-PAR0009 E 02-grammar an angle bracket of a type list is missing A list of type arguments <…> or of type parameters is not closed by >.
    LYR-PAR0010 E 03-types a tuple of fewer than two elements, or a label given twice A tuple literal or tuple type is written with one element and a comma, (1,), or a tuple type gives the same label to two elements.
    LYR-PAR0011 E 02-grammar a type is missing A type is needed — after :, in a type argument list, after as or is — and the token there begins none; or a dotted type path ends in something else than a name.
    LYR-PAR0012 E 08-expressions a lambda without '=>' before its body A lambda's parameters, or its parameters and return type, are not followed by =>; or the parameters of a trailing block { a, b => … } are not.
    LYR-PAR0013 E 08-expressions a lambda parameter without a name Where a lambda's parameter name belongs stands something else — a literal, or a reserved word, which is then read as the name it was meant to be.
    LYR-PAR0014 E 08-expressions an interpolation not closed by '}' In an f-string, the expression of an interpolation {…} is followed by something else than its } or its format spec :…} — a second expression, a stray ), or the end of the line.
    LYR-PAR0015 E 03-types a function type without '->' A function type fn(…) is not followed by -> and its return type.
    LYR-PAR0016 E 07-statements a ';' is missing A statement is not ended by ;; a function has neither a body { … } nor a ;; an extern declaration is not ended by ;. Within a statement block, a value without ; before the end of a block is refused too.
    LYR-PAR0017 E 07-statements a '{' is missing, or a body without braces The body of if, else, while, do or for is a single statement without braces, or a block, a match body, or the body of a struct, class, enum, interface or extend does not open with {.
    LYR-PAR0018 E 02-grammar a '}' is missing A { is not closed by its }: a block, a match body, a declaration's body, an initializer, a with, an import list, attribute arguments, a quote or splice, a trailing block — or the ) of an attribute's one value is missing.
    LYR-PAR0019 E 07-statements a '(' is missing after a keyword if, while, for, match or catch is not followed by (, or a function's name is not followed by its parameter list.
    LYR-PAR0020 E 07-statements a binding without its name, pattern or value A let, var, loop variable or catch binding has no name (a reserved word stands there, read as the name); a pattern binding or destructuring has no = and value; a let condition has no =; or a module-level or static binding takes a pattern.
    LYR-PAR0021 E 07-statements a for loop without 'in' The header of a for loop has its variable or pattern but no in before what it walks.
    LYR-PAR0022 E 07-statements a do block without 'while' The block of a do loop is not followed by while and its condition.
    LYR-PAR0025 E 02-grammar something else than a declaration at module level At the top level of a file stands a token that begins no declaration — a statement, an expression, a stray brace. The parser skips to the next declaration.
    LYR-PAR0026 E 02-grammar a name is missing Where a declaration, a parameter, a field, a variant, a type parameter, an attribute, an import item or a path segment is named, no name stands — or a reserved word, which is then read as the name; an import list { } names nothing; a bare ... closes the parameters of a function that is no extern "C" one.
    LYR-PAR0028 E 03-types a type alias without '=' A type or opaque type declaration names the alias, and its type parameters, but no = follows.
    LYR-PAR0029 E 03-types fields of a struct or class without ',' between them In the body of a struct or class, a field is followed by another member without a , between them.
    LYR-PAR0030 E 05-interfaces a list after '::' without its '[' The interfaces after :: — of a struct, class, enum, interface or extend block, of a type parameter's constraints, of an associated type's bound — do not open with [.
    LYR-PAR0031 E 02-grammar a parameter or field without ':' before its type A function's parameter or a field of a struct, class or variant is named, and no : follows before its type.
    LYR-PAR0032 E 03-types a function without 'fn', or its words out of order Where a function or method is declared, fn is missing after its other words, or inline static is written where the order is static inline; an extern block declares no function.
    LYR-PAR0033 E 09-patterns a malformed pattern Where a pattern stands, the token begins none; a - in a pattern is not followed by a number; a range pattern's bound is no literal; or an array pattern holds two rests ...
    LYR-PAR0034 E 09-patterns a match arm without '=>' A match arm's pattern, or its guard, is not followed by =>.
    LYR-PAR0035 E 09-patterns match arms without ',' between them A match arm whose body is an expression is followed by another arm without a ,.
    LYR-PAR0036 E 08-expressions an if expression without 'else' An if in expression position — after =, as an argument, without braces around its branch — has no else branch.
    LYR-PAR0037 E 03-types a field in an initializer without '=' In a struct initializer, in the braces of an attribute, or after [f] in an initializer over infos, a field's name is not followed by =.
    LYR-PAR0041 E 05-interfaces a static member in an interface (retired) An interface member is declared static. Retired: In Lyric 5 an interface declares static members, which a constraint reaches, and every member sequence admits static
    LYR-PAR0042 E 11-metaprogramming an attribute with no declaration to carry it An attribute stands at the end of a file, before something that is no declaration, before an import, or before an extern block, whose functions carry their own.
    LYR-PAR0043 E 03-types an inline array of no positive literal length An inline array type T[n] gives a length that is not a positive decimal literal: int[0], int[0x4].
    LYR-PAR0044 E 13-abi an extern symbol that is not a string An extern declaration has = after its signature, and no string literal follows to name the symbol.
    LYR-PAR0045 E 02-grammar nesting deeper than the parser carries Expressions or types in a file nest deeper than this implementation parses — 192 levels of parentheses, brackets, operands or type arguments. Reported once, and the file is then read as holding no declaration.
    LYR-PAR0046 E 07-statements a label on something that is no loop A label name: stands before a statement that is not while, do, for or loop.
    LYR-PAR0047 E 05-interfaces 'by' where nothing is delegated An entry of the interface list of an enum, of an interface's parents, or of an extend block names a field to delegate to with by.
    LYR-PAR0048 E 05-interfaces 'sealed' before something that is no interface The word sealed stands before a struct, class, enum, function or other declaration that is not an interface.
    LYR-PAR0049 E 06-errors several types not in brackets, or an empty type list Several types follow throws, or a catch binding's : or in, without brackets around them; or a bracketed list after throws, catch (e in …) or a pattern's in is empty.
    LYR-PAR0050 E 06-errors a 'try' that changes the value, not at the start try? or try!, or a try with catch clauses, stands to the right of an operator instead of at the start of the expression it covers.
    LYR-PAR0051 E 06-errors a 'catch' clause on 'try?' or 'try!' A try? or try! expression is followed by catch clauses.
    LYR-PAR0052 E 06-errors a 'using' that is not one 'let' with a value using var is written, or a using binding takes a pattern or has no value.
    LYR-PAR0053 E 04-modules a visibility word where none or another belongs A declaration or member has two visibility words (pub private), an enum variant has one, or an import has one other than pub.
    LYR-PAR0054 E 08-expressions '&' outside an argument The mark & stands before an operand that is not an argument of a call — in a binding, an operation, a returned value.
    LYR-PAR0055 E 03-types an initializer at the start of a statement A statement begins with Name { … } whose braces read as an initializer's: Point { x = 1 };, or a call with a trailing block whose assignment lost its ;, run { total = 5 }.
    LYR-PAR0056 E 06-errors a 'throws' behind a function type that is a return type A declaration's or lambda's return type is a function type without parentheses, followed by throws: fn make(): fn() -> int throws E.
    LYR-PAR0057 E 03-types an enum's variants not ended by ';' before its members In an enum body a member — fn, static, an attribute, type Item = — stands where the next variant's name is expected: the ; after the variants is missing.
    LYR-PAR0058 E 03-types '&' before a lambda parameter's pattern A lambda parameter written as a pattern in parentheses carries the place mark &: (&(a, b)) => ….
    LYR-PAR0059 E 08-expressions comparisons or equalities chained A comparison (<, <=, >, >=, in, not in) is followed by another one, or == or != by another, as in a < b < c or a == b == c.
    LYR-PAR0060 E 03-types a local function that is not one plain closure A fn declared inside a function body has type parameters, a parameter with a default value or a variadic parameter, or has no body.
    LYR-PAR0061 E 11-metaprogramming a 'comptime if' in expression position without 'else' A comptime if (c) a stands where a value is taken and has no else branch.
    LYR-PAR0062 E 11-metaprogramming a 'comptime for' in an initializer without '[f] = e' In an initializer, a comptime for (f in …) is followed by something else than an item [f] = e.
    LYR-PAR0063 E 11-metaprogramming 'quote' without a block The word quote is not followed by {.
    LYR-PAR0064 E 16-diagnostics a field that ends with ';' A field of a struct or class, or a field of an initializer, ends with ; where its list separates with ,; read as the , it stands for.
    LYR-PAR0065 E 16-diagnostics a 'continue', 'break' or 'return' where a value stands A jump stands where an expression is wanted — a match arm, a branch of an if expression —; it is a statement and goes in a block, => { continue; }.

    A.3 RES — Names and modules

    The resolver's: what a name, an import or a module path refers to.

    Code S Chapter Title When
    LYR-RES0001 E 04-modules a name declared twice in one scope Two declarations take the same name in one scope: a module, a type's members, an extend block, an import beside a declaration, or a parameter list. The second is reported; the first stays.
    LYR-RES0002 E 04-modules a type name that names no type A type annotation names a type that is neither declared in the module, imported, a builtin, nor passed on by the prelude.
    LYR-RES0003 E 04-modules an import of a module that does not exist An import names a module that no file provides: no src/<path>.lyr in the package, no module of a dependency or of std by that path.
    LYR-RES0004 E 04-modules an imported name the module does not declare A selective import import m { x }; asks for a name the module m neither declares nor passes on with pub import.
    LYR-RES0005 E 04-modules modules that import each other The imports of the program's modules form a cycle: a module imports, directly or through others, a module that imports it.
    LYR-RES0006 E 04-modules a file whose module header disagrees with its path (retired) A file loaded for an import declared, in its module header, a different module than the path it was found at. Retired: Lyric 5.0: a module is named by its path alone and the module header is refused (LYR-RES0008), so a header can no longer disagree with the path
    LYR-RES0007 E 04-modules two files that are the same module Two source files of a package map to the same module path, for example src/geo/point.lyr and src/geo.point.lyr, which are both app.geo.point. Reported where every file of the package is compiled: when a library is built, and by lyric test.
    LYR-RES0008 E 04-modules a module header A file begins with a module header that names a path: module tools.gen;.
    LYR-RES0009 E 04-modules a name the place may not see A use or an import reaches a declaration its visibility hides from this place: a private name from another module, an internal name from another package, a hidden field, or another module's import.
    LYR-RES0010 E 04-modules a pub import of a name that is not pub A pub import passes on a name that is not pub where it is declared.
    LYR-RES0011 E 04-modules a declaration that takes a builtin type's name A top-level declaration is named like a builtin type: struct int, fn string().
    LYR-RES0012 E 04-modules a name that is also a submodule A module declares or imports a name that is also the last segment of one of its submodules: http in app.net beside the file src/net/http.lyr. Reported whether or not the submodule is imported.
    LYR-RES0013 E 15-project a single file named std.lyr A file built by itself, outside a package, is named std.lyr: its module would be named std.
    LYR-RES0014 E 15-project an import of a package the manifest does not declare A module imports from a package that its own package's lyric.toml does not list under [dependencies], such as a dependency of a dependency.
    LYR-RES0015 E 15-project a test module under both src/tests/ and tests/ lyric test finds the same test module twice: as src/tests/<name>.lyr and as tests/<name>.lyr. Both are the module <package>.tests.<name>; the run stops before anything is compiled.

    A.4 SEM — Semantic errors and warnings

    The checker's: types, interfaces, errors, patterns, and the warnings.

    Code S Chapter Title When
    LYR-SEM0001 E 03-types a value of another type than the place takes An expression's type does not fit where it stands: an initializer, an argument, a return value, an assignment.
    LYR-SEM0002 E 04-modules a name that nothing in scope declares An identifier in an expression names no local, parameter, function, global or imported item visible at that point. The message may carry a did-you-mean note.
    LYR-SEM0003 E 03-types an operator its operands do not provide An operator is applied to a type it is not defined for: arithmetic on a bool or char, < on a type without Ordered, + on a type without the operator interface, same on values that are not references, or a compound assignment through an operator interface on a field or element.
    LYR-SEM0004 E 07-statements a condition that is not a bool The condition of an if, while, do … while or a guard has a type other than bool.
    LYR-SEM0005 E 03-types a null operator on a value that is never null A force-unwrap !, a ?? or a ??= is applied to a type that is not optional, so the null case it handles cannot happen. A bare type parameter counts as not optional.
    LYR-SEM0006 E 03-types a conversion that does not exist An as between types it does not convert (it converts numbers only, and char to and from uint32), or an f-string hole whose value has no Display conformance or carries a format specifier Display does not take.
    LYR-SEM0007 E 03-types a value that cannot be indexed or iterated An index whose type is not int (or an integer type that widens to it), an index or range on a type that provides none, or a for over a value that is not an Iterable.
    LYR-SEM0008 E 05-interfaces this outside a method The keyword this appears where there is no receiver: in a free function or in a module-level initializer.
    LYR-SEM0009 E 08-expressions array elements of different types An array literal without an expected type has elements whose types differ from the first element's.
    LYR-SEM0010 E 07-statements a binding whose type nothing fixes A local, global or static binding has neither a declared type nor an initializer, or its only initializer is null or [], which fix no type on their own. A static member of an interface without a type is reported here too.
    LYR-SEM0011 E 03-types a name in type position that is no type A type name, an initializer T { … } or an attribute names something that is not a type, or nothing at all. A non-type name before braces is also reported here, since the braces then read as an initializer's fields.
    LYR-SEM0012 E 05-interfaces a member the type does not have A member access x.name names no field, method or element of the value's type, or reads a member that is a method without calling it (length instead of length()). A tuple position past its last element is reported here too.
    LYR-SEM0013 E 08-expressions a call on something that is not a function A call f(…) whose callee is not a function value: a number, a field that is no function, or a type T(…) that declares no static fn new.
    LYR-SEM0014 E 08-expressions a call with the wrong number of arguments A call gives fewer arguments than the function's required parameters or more than it takes, or a call with named arguments leaves out a parameter that has no default.
    LYR-SEM0015 E 03-types a field the type does not declare An initializer T { name = … }, a struct variant's initializer or a field pattern names a field that the struct, class or variant does not declare.
    LYR-SEM0016 E 08-expressions branches whose types do not unify The branches of an if expression, the arms of a match expression, the parts of a try expression or the yields and returns of an inferred lambda produce types that have no common type.
    LYR-SEM0017 E 07-statements a path of a function that returns no value A function whose return type is not void has a path that reaches the end of its body without a return or a throw. A function returning never whose body can end, and a coroutine whose result is not returned on every path, are reported here too.
    LYR-SEM0018 E 07-statements a variable read before it is surely assigned A local declared without an initializer is read on a path where no assignment has reached it.
    LYR-SEM0019 E 03-types a write to something that cannot be written An assignment, ++/--, an index write or a call of a mut fn targets something that is not a writable place: a let, a parameter, a field without var, a temporary, a module let, a value reached through a let or through an optional chain.
    LYR-SEM0020 E 05-interfaces a conformance that leaves an interface member unimplemented A type or a conformance block declares an interface but does not implement one of its abstract methods, or does not answer one of its static lets.
    LYR-SEM0021 E 04-modules a missing, duplicated or malformed main The entry module has no main, declares it twice, or declares it with parameters or with a return type other than void or int.
    LYR-SEM0022 E 07-statements an expression statement without an effect A statement consists of an expression whose value is discarded and which does nothing else: a literal, a name, an arithmetic expression, a with. Only calls, assignments, ++/--, throw and loops stand alone.
    LYR-SEM0023 E 05-interfaces a mut function that has nothing to write mut is written on a free function, which has no receiver, or on a method of a type that has no var field and whose body does not replace this (unless an interface demands the method as mut).
    LYR-SEM0024 E 08-expressions a variadic parameter out of place A variadic parameter name: T... is not the last parameter or has a default, or a parameter is written with Lyric 4's params.
    LYR-SEM0026 E 03-types the wrong number of type arguments A generic type, alias or function is given more or fewer type arguments than it declares type parameters (after defaults), or a function that is not generic is given type arguments.
    LYR-SEM0027 E 05-interfaces a member of a type parameter that no constraint provides A generic body uses a member on a value of a type parameter (or of an associated type) that none of the parameter's constraints, and no blanket block they admit, declares.
    LYR-SEM0028 E 05-interfaces a type argument that does not satisfy its constraint A type argument, written or inferred, does not conform to an interface its type parameter is constrained by.
    LYR-SEM0029 E 09-patterns a pattern that cannot match the scrutinee's type A pattern's shape does not fit the scrutinee's type: null against a non-optional, a literal or range of another type, a tuple pattern of another arity, an array pattern against a non-array, or a dotted variant path against a type that is not an enum.
    LYR-SEM0030 E 06-errors a thrown, declared or caught type that is not an Error A throw throws a value, a throws clause lists a type, or a catch names a type that does not conform to Error.
    LYR-SEM0031 E 09-patterns an enum variant used against its shape A variant is constructed or matched in a form its declaration does not have: a struct variant called like a function, a tuple variant built with braces, a payload pattern on a variant without one, or a variant name the enum does not declare.
    LYR-SEM0032 E 09-patterns or-pattern alternatives that bind differently The alternatives of an or-pattern p \| q do not bind the same names, or bind one name at different types.
    LYR-SEM0033 E 08-expressions a block that gives no value where one is wanted A block that stands where a value is wanted — an arm of a match expression beside arms that give values, a clause of a try expression, a block expression — ends without a tail expression and does not leave on every path.
    LYR-SEM0034 E 06-errors an error that nothing handles A call, throw or other site may throw an error type that no surrounding catch takes and the enclosing function's throws does not declare. In a lambda, an initializer or a detached body, where nothing can be declared, the error has to be caught there.
    LYR-SEM0035 E 06-errors a catch-all clause before another clause A catch clause without a type, which takes every error, is followed by further catch clauses.
    LYR-SEM0036 E 06-errors a try block without a catch A try { … } block statement has no catch clause.
    LYR-SEM0038 E 10-concurrency a bare yield in a coroutine that yields values A yield; without a value stands in a coroutine whose yield type is not void.
    LYR-SEM0039 E 10-concurrency a value returned from a coroutine that returns nothing A return v; with a value stands in a coroutine whose type gives no result, Coroutine<Y> rather than Coroutine<Y, R>.
    LYR-SEM0042 E 05-interfaces an implementation that does not match the interface's signature A method or static that implements an interface member differs from the member's declaration: in parameters, return type, mut, static, place parameters, the errors it throws, or the answer it gives an associated type the interface fixes.
    LYR-SEM0043 E 05-interfaces one member defaulted by two interfaces A type conforms to two interfaces that both provide a default for a member of one name, and the type implements the member itself nowhere.
    LYR-SEM0045 E 03-types a lambda parameter whose type nothing gives A lambda parameter has no written type and the lambda stands where no function type is expected, or a trailing lambda's implicit it stands where the expected function does not take exactly one parameter.
    LYR-SEM0046 E 10-concurrency a lambda that can end without its value A block lambda whose result is not void — a generator lambda with a result, or a lambda an inline function sets in place — has a path that ends its body without returning the value.
    LYR-SEM0047 E 05-interfaces an extend target or conversion not supported An extend block targets an inline array T[N], or something that is no named type and no built-in constructor.
    LYR-SEM0050 E 09-patterns a match that does not cover every value The arms of a match leave values of the scrutinee's type unmatched: a variant, null, a conformer of a sealed interface, a length class of an array, or the rest of an open type. The message names a missing pattern. Guarded arms do not count.
    LYR-SEM0051 E 13-abi a function without a body A function declaration outside the standard library has no body and is not an extern declaration.
    LYR-SEM0052 E 03-types a type, module or generic function used as a value A name that is not a value — a type, a module, an interface — stands where a value is wanted, or the bare name of a generic function is used as a function value.
    LYR-SEM0053 E 11-metaprogramming an attribute used as an expression An @Name stands where an expression is expected. Attributes describe the declaration they precede and have no value.
    LYR-SEM0054 E 03-types a static member declared 'mut' A member function is declared both static and mut.
