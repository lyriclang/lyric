Child processes for tasks: start a program, write to its stdin, readSomeOut/ readSomeErr its streams, wait for its exit code — every waiting form yielding to the scheduler instead of blocking the thread.

The silent forms answer whether (null/false); the OrThrow twins say why with an IoError — NotFound when the program does not exist, PermissionDenied when it may not be run. The streams speak readSome's three truths: bytes are bytes, an EMPTY array is the stream being done (EOF), and null is a failure.

Carries processAccess, its own capability bit: starting programs is a new power, not an osAccess refinement.

readSomeOut function

pub fn readSomeOut(child: Child, max: int): ?uint8[]

Waits for bytes on the child's standard output and reads up to max of them. Three truths in one answer: bytes are bytes, an EMPTY array is the stream being done (EOF), and null is a failure — readSomeOutOrThrow says which.

write function

pub fn write(child: Child, bytes: uint8[]): bool

Hands bytes to the child's standard input. The write is queued and drained in the background; false once the child's stdin broke — a child that exited without reading everything is the usual way.
