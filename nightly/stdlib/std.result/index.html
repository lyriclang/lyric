A failure as a value: Ok(value) or Err(reason), and the combinators that compute with either without testing first.

throws remains the language's mechanism; this is the holder for a failure that is stored, collected or handled later. orThrow and fromOptional are the bridges to throws and ?T.

Result enum

pub enum Result<T, E>

The outcome of something that can fail: the value, or the reason it did not happen.

Two variants and nothing else, so a match covers it with two arms. The reason type E is unconstrained — a string is a fine reason for a config line, and orThrow alone asks for a Throwable.

Ok(T)

It happened, and this is the value.

Err(E)

It did not, and this says why.

pub fn isOk(): bool

Whether this is an Ok.

pub fn isErr(): bool

Whether this is an Err.

pub fn ok(): ?T

The value as an optional: null for an Err, which drops the reason — the bridge to ?? and to every function that takes a ?T.

Not available when T is itself optional: the answer would be ??T. A match tells Ok(null) from Ok(v) there, which is the distinction this would have collapsed anyway.

pub fn err(): ?E

The reason as an optional: null for an Ok.

pub fn unwrapOr(fallback: T): T

The value, or fallback for an Err. The fallback is evaluated either way; for one that costs something, unwrapOrElse takes a function.

pub fn unwrapOrElse(fallback: fn(E) -> T): T

The value, or what fallback makes of the reason — the reason is not lost, it is handed to the function that decides what stands in for the value.

pub fn expect(message: string): T

The value, or a panic carrying message — for a result that CANNOT be an Err here, where being wrong about that is a programming error. As std.option.expect for ?T.

andThen function

pub fn andThen<T, E, U>(r: Result<T, E>, f: fn(T) -> Result<U, E>): Result<U, E>

As map, but f may itself fail: the first Err in a chain wins, and everything after it is skipped. andThen(andThen(parse(a), lookup), validate) reads as the three steps it is.

orElse function

pub fn orElse<T, E, F>(r: Result<T, E>, f: fn(E) -> Result<T, F>): Result<T, F>

A second attempt when the first failed: f gets the reason and answers a result of its own. The mirror image of andThen.

orThrow function

pub fn orThrow<T, E :: [Throwable]>(r: Result<T, E>): T throws E

The value, or the reason THROWN — the bridge from the value form back to the language's mechanism, for the moment a stored failure is finally handled.

The catch that goes with it is catch (e: Throwable) today: the compiler substitutes a throws clause's type parameter at no call site yet, so a catch (e: IoError) beside it is reported as not covering. That is a compiler limitation, not a property of this function.

stdlib/std/result.lyr:155

fromOptional function

pub fn fromOptional<T, E>(o: ?T, error: E): Result<T, E>

An optional with a reason attached: the value when there is one, error when there is not. What turns a Map.get or a parseInt into a result without a match at every site.

Not instantiable for an optional T, for the reason ok is not: the parameter would read ??T. Result<?U, E>.Ok(value) is the direct construction there.
