Iterator interface

pub interface Iterator<T>

A cursor: next() yields values until null says the end. That is the whole interface — there is no hasNext beside it that could fall out of step.

mut fn next(): ?T

The next value, or null at the end. mut, because an iterator advances its own position.

fn map<U>(f: fn(T) -> U): Iterator<U>

Each element through f, lazily: nothing runs before someone asks.

fn filter(keep: fn(T) -> bool): Iterator<T>

The elements keep accepts, lazily.

fn take(count: int): Iterator<T>

At most count elements, then the end.

fn skip(count: int): Iterator<T>

Everything after the first count elements.

fn takeWhile(keep: fn(T) -> bool): Iterator<T>

Elements while keep accepts, then the end — unlike filter, which keeps looking.

fn zip<B>(right: Iterator<B>): Iterator<(T, B)>

Pairs, ending when either side does.

fn chain(second: Iterator<T>): Iterator<T>

This sequence, then second.

fn flatMap<U>(f: fn(T) -> Iterator<U>): Iterator<U>

Each element into an iterator of its own, flattened.

Iterable interface

pub interface Iterable<T>

What can be walked: for (x in e) calls iter() on anything satisfying this.

A container SAYS how to walk it rather than being the cursor itself — were List<T> its own Iterator<T>, two loops over the same list would push each other along. Every call hands out a FRESH cursor.

fn iter(): Iterator<T>

A fresh cursor over this value.

over function

pub fn over<T>(xs: T[]): Iterator<T>

A cursor over an array: over(xs).map(f) starts a chain where for (x in xs) starts a loop.

The index belongs to the cursor, so two chains over one array do not disturb each other.

stdlib/std/iter.lyr:241

compact function

pub fn compact<T>(xs: (?T)[]): Iterator<T>

The values of an array of optionals that are not null, lazily.

The commonest table with holes in it is a (?T)[] — a fixed number of slots, most of them empty — and this is what makes one chainable: compact(houses).map(rooms).

It takes an ARRAY rather than an iterator, and that is not a convenience. An Iterator<?T> cannot exist: next() answers ?T and spends null on "the end", so an optional element would need ??T to be told apart from it, and ? does not nest. Reading the slots directly is what makes the distinction available at all.

fold function

pub fn fold<T, A>(source: Iterator<T>, seed: A, step: fn(A, T) -> A): A

Folds from the left: fold(1..4, 0, (acc, n) => acc + n) is ((0+1)+2)+3.

The most general terminator; count, sum, any and all are special cases of it. They exist separately because fold with a closure is too much ceremony for counting.

collectArray function

pub fn collectArray<T>(source: Iterator<T>): T[]

Everything into an array.

Quadratic: a T[] has a fixed length, so every append copies. For large iterators use std.collections.collect, which gathers into a doubling List<T>. It stands here because std.iter must not import std.collections; the dependency runs the other way.
